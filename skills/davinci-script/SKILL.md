# ฟังก์ชัน 7: เขียนสคริปต์ → teleprompter

## 1. กฎการเขียน = skill ของผู้ใช้เอง (ห้ามเขียนกฎซ้ำที่นี่)
- กฎทั้งหมด (โหมดเรื่อง, hook, scene architecture, ความปลอดภัยเรื่องบุคคลจริง, ความยาว, Shorts, live, lessons log) มาจาก skill **action-story-channel-script** ของผู้ใช้
- ให้ใช้**เวอร์ชันล่าสุด**เสมอ:
  1. หาไฟล์ด้วยคำสั่ง `ls -t ~/.claude/skills/synced/*/action-story-channel-script/SKILL.md ~/.claude/skills/*/SKILL.md` แล้วเลือกไฟล์ที่ `name:` เป็น action-story-channel-script และแก้ไขล่าสุด (ปัจจุบันคือชุดที่ sync จาก claude.ai)
  2. อ่านทั้งไฟล์ด้วย Read ก่อนเริ่มเขียน (หรือเรียกผ่าน Skill tool ถ้ามีให้ใช้)
- ถ้ากฎในไฟล์นั้นขัดกับข้อใดในหน้านี้ **ให้ทำตามไฟล์นั้น** เช่น ประโยคเปิด "วันนี้เราจะมาพูดถึงเรื่อง..." และคำต้องห้าม "จิ๊กซอว์"

## 2. รูปแบบ hook ประจำช่อง (บังคับทุกสคริปต์วิดีโอ)
ผู้ใช้กำหนดให้ hook เปิดและปิดด้วยรูปแบบเดียวกันทุกตอน:
1. **ประโยคแรกของสคริปต์:** `วันนี้เราจะมาพูดถึงเรื่อง [หัวข้อ]` ตรงตามคำนี้ทุกคำ ใช้ครั้งเดียว และหัวข้อต้องสั้นและชวนสงสัยตามกฎของ skill ผู้ใช้
2. **เนื้อ hook:** ตาม hook recipe ของ skill ผู้ใช้ ได้แก่ เหตุผลที่เรื่องนี้แปลก → ข้อเท็จจริงที่ชวนสงสัย 2–3 ข้อ → คำถามหลัก → teaser ของสิ่งที่เจอทีหลัง → lead-in (ชื่อคดี หรือคนที่เราจะตามดูผ่านสายตา)
3. **ประโยคสุดท้ายของ hook = ประโยคส่งเข้าเรื่อง** สั้น เป็นประโยคเดียว ลงท้ายด้วย "ครับ" และไม่มีข้อมูลใหม่หลังจากนั้น เลือกจากชุดนี้ หรือสำนวนใกล้เคียงในรูปแบบเดียวกัน:
   - "เดี๋ยวเราไปดูกันครับ"
   - "ไปฟังกันเลยครับ"
   - "ไปดูกันเลยครับ"
   - "เดี๋ยวเราไปฟังกันครับ"
   - ต่อท้าย lead-in ได้ เช่น "…ผ่านสายตาของแอร์โฮสเตสที่ชื่อทีน่า เดี๋ยวเราไปดูกันครับ"
   - **ห้ามใช้ประโยคเดียวกันทุกตอนติดกันเกิน 3 ตอน** ให้สลับในชุดนี้เพื่อไม่ให้ฟังเป็นสูตร
4. หลังประโยคส่งเข้าเรื่อง ตามด้วย `[INTRO / โฆษณา]` (ถ้ามี) แล้วจึงเข้าฉากปูเรื่อง
5. Shorts ไม่ต้องใช้รูปแบบนี้ ให้ตามกฎ Shorts ของ skill ผู้ใช้
6. **ตรวจก่อนส่งทุกครั้ง:** `make_prompter` คืนค่า `hook_check` (เปิดถูกไหม / ปิดด้วยประโยคส่งเข้าเรื่องไหม) ถ้าไม่ผ่าน ให้แก้ก่อนส่ง

## 2b. ส่วนที่ DaVinci Bot เพิ่ม (ต่อจากการเขียน)
1. **ที่เก็บไฟล์:** `~/Desktop/Agent-M/<ชื่อเรื่อง>/<topic>_script_vN.md` (และ `_briefing_vN.md`, `_livestream_vN.md`) ตามแบบเดิมของผู้ใช้ ถ้าเป็นเวอร์ชันใหม่ ให้เพิ่มเลข vN ห้ามเขียนทับไฟล์เดิม
2. **ความยาว: ค่าเริ่มต้นคือ "ไม่จำกัด"** ให้ยาวตามความเข้มข้นของเรื่อง ห้ามตัดฉากหรือแบ่งตอนเพียงเพราะยาว
   - ถ้าผู้ใช้ไม่ได้ระบุความยาว = ไม่จำกัด ให้บอกไว้ใน creative brief ว่า "ความยาว: ไม่จำกัด (ตามเนื้อเรื่อง)" และไม่ต้องถามซ้ำ
   - ยังต้อง**นับและรายงานความยาว**ทุกครั้งตาม Step 5 ของ skill ผู้ใช้ เพื่อวางแผนอัดและตัดต่อ แต่ห้ามเสนอให้ตัด เว้นแต่ผู้ใช้ถาม
   - **กติกา "ยาวได้ แต่ห้ามยืด"** (ใช้ทุกครั้งที่ไม่จำกัดความยาว หรือบทยาวกว่า ~30 นาที):
     1. ทุกฉากต้องผ่าน scene audit ของ skill ผู้ใช้: มีปัญหา มีจุดพีค และจบด้วยคำถามหรือจุดหักเห ฉากที่ไม่เพิ่มอะไรให้ตัด เพราะยืด ไม่ใช่เพราะยาว
     2. **มี re-hook ทุก 5–8 นาที**: เปิดปมใหม่ก่อนปิดปมเก่า (open loop ซ้อนกัน) หรือประโยคชวนอยู่ต่อที่ผูกกับเรื่องจริง ("แต่ที่ FBI ยังไม่รู้ตอนนั้นคือ...") ห้ามใช้ประโยคลอยๆ
     3. **ห้ามพูดซ้ำข้อมูล** ยกเว้น recap สั้นๆ 2–3 ประโยคทุก ~15–20 นาที สำหรับคนที่เพิ่งเข้ามาหรือกลับมาดูต่อ (แบบ recap card ในสคริปต์ไลฟ์)
     4. **สลับจังหวะเร็วและช้า** ไคลแมกซ์ต้องยาวและละเอียดที่สุด ไม่ใช่สั้นที่สุด
     5. **production notes ต้องมี:** chapters/timestamps สำหรับ YouTube, จุดวางโฆษณากลางคลิปที่ตรงกับจุด cliffhanger, และแผนอัด (แบ่ง block 20–25 นาที / กี่ session ตามแผนฝึก A2)
     6. ถ้าเรื่องยาวมากจนอยากแบ่งตอน ให้**เสนอเป็นทางเลือก**พร้อมจุดแบ่งที่เป็น cliffhanger โดยค่าเริ่มต้นยังคงเป็นคลิปเดียว
3. **เมื่อผู้ใช้กำหนดความยาว** ให้เช็คงบ (แผนฝึก A1, `reports/training-plan-*.md`):
   - นับแบบเดียวกับ Step 5 ของ skill ผู้ใช้ (`wc -m` = ทุกตัวอักษรรวมสระ วรรณยุกต์ และช่องว่าง) ซึ่ง `make_prompter` นับแบบนี้อยู่แล้ว
   - ความยาวหลังตัด ≈ ตัวอักษร ÷ 600 + 4–5 นาที: คลิป 20 นาที ≤ ~9,500, 25 นาที ≤ ~12,500, 30 นาที ≤ ~15,500 ตัวอักษร
   - ใช้ `make_prompter` หรือ `script_digest` นับความยาวจริง ถ้าเกินงบเกิน 15% ให้บอกตรงๆ แล้วเสนอฉากที่ตัดได้หรือจุดแบ่งตอน ให้ผู้ใช้เลือก
   - **production notes ต้องเป็นตัวเลขที่นับจากบทจริง** ห้ามคัดลอกตัวเลขจากเวอร์ชันเก่า (เคยเกิดใน MH370 v2 ที่หมายเหตุยังเขียน 44,700 ตัวอักษร แต่บทจริงมี ~15,900)
4. **teleprompter:** เมื่อผู้ใช้ล็อกสคริปต์แล้ว (หรือขอ) ให้เรียก `make_prompter(script_path)` จะได้ `<topic>_prompter.html` + `.txt` ข้างสคริปต์ แล้วแจ้งวิธีใช้:
   - Space = เริ่ม/หยุด, ↑↓ = ความเร็ว, +/− = ขนาดตัวอักษร, M = กลับด้านสำหรับ teleprompter กระจก
   - ใช้ตามแผนฝึก A2: อัด hook และ CTA ก่อน แล้วอัดเป็น block 20–25 นาที
   - บทยาวมาก (เกิน ~50 นาที): เสนอให้สร้าง prompter แยกตามช่วง (part 1/2/3) ตามแผนอัด
5. **ส่งต่อให้ฟังก์ชันอื่น:**
   - จุดตัด Shorts ในสคริปต์ → หลัง rough cut ใช้ทำคลิปสั้น (ฟังก์ชัน 1 ขนาด 9:16 + ฟังก์ชัน 2 ซับ pop)
   - `[ภาพ: ...]` และภาคผนวกภาพ → ใช้เป็นคำค้นของ B-roll (ฟังก์ชัน 3)
   - โทนของเรื่อง (โศกนาฏกรรมหรือไม่) → ใช้กำหนดกฎ SFX (ฟังก์ชัน 4)
6. **ไม่ต้องใช้ Resolve** ในฟังก์ชันนี้ (เขียนสคริปต์ได้แม้ Bridge ไม่ได้เปิด)

## 3. ส่งมอบ
- path ของสคริปต์ (+ briefing/prompter ถ้ามี), ความยาวที่นับจริง, creative brief 6–8 บรรทัดตามที่ skill ผู้ใช้กำหนด และคำถามปิดท้าย
- ในหน้าเว็บ ไฟล์ .md จะแสดงเป็นลิงก์ ส่วน prompter.html ให้บอก path เต็มเพื่อเปิดในเบราว์เซอร์
