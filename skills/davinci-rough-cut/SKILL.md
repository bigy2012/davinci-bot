# ฟังก์ชัน 1: Rough Cut

เป้าหมายคือเอาฟุตเทจพูดหน้ากล้องที่มีการพูดซ้ำ พูดผิด และช่วงเงียบ มาทำเป็นคลิปที่**ฟังแล้วเหมือนพูดรอบเดียวจบ** โดยใช้เทคที่ดีที่สุดของทุกประโยค และต่อกันตามบริบทของเรื่อง

ผู้ใช้เป็นคนกำหนดงานทุกครั้ง ห้ามเริ่มตัดก่อนได้ brief และห้ามสร้าง timeline ก่อนผู้ใช้อนุมัติแผน

## ขั้นที่ 0: เช็คความพร้อม
เรียก `resolve_status` ถ้า bridge ไม่ตอบ ให้บอกผู้ใช้ไปที่ Resolve → Workspace → Scripts → DaVinci Bot Bridge

## ขั้นที่ 1: Brief (ถามเฉพาะข้อที่ผู้ใช้ยังไม่ได้บอก รวมเป็นข้อความเดียว พร้อมค่าแนะนำ)

| ข้อ | ตัวเลือก | ค่าแนะนำ |
|---|---|---|
| ไฟล์ต้นฉบับ | path ไฟล์/โฟลเดอร์ + ลำดับ | เรียงตามชื่อไฟล์ (= เวลาถ่าย) |
| สคริปต์ | วางสคริปต์ / ไม่มี | ไม่มี → ยึดเรื่องที่ผู้พูดตั้งใจเล่า |
| จังหวะ (pace) | tight / natural / relaxed | tight (ช่องว่างกระชับ ดูหัวข้อ **จังหวะ**) |
| สไตล์การตัด | jump cut ล้วน / + punch-in / + J-L cut | jump cut + L-cut ตอนขึ้นประโยคใหม่ **ไม่ใช้ punch-in** |
| คำลงท้าย ครับ/นะครับ | เก็บ / ตัดเมื่อเกินจำเป็น | เก็บ |
| ความยาวเป้าหมาย | ไม่กำหนด / X วินาที | ไม่กำหนด |
| ขนาดภาพ | ตามต้นฉบับ / 1080x1920 / 1920x1080 | ตามต้นฉบับ |
| ชื่อ timeline | | `roughcut <ชื่อเรื่อง> v1` |

ถ้ามีความยาวเป้าหมายแล้วเนื้อหาเกิน ให้เสนอว่าจะตัดประโยคไหนออกและให้ผู้ใช้เลือก ห้ามตัดเนื้อหาเองเงียบๆ

## ขั้นที่ 2: วิเคราะห์
- เรียก `analyze_speech(path)` ทีละไฟล์ จะได้ unit (ช่วงพูดระหว่างช่วงเงียบ) และ reference transcript
- **เวลา**: เชื่อขอบของ unit ซึ่งมาจากพลังงานเสียงและแม่นระดับ 10ms
- **ถ้อยคำ**: ข้อความใน unit สั้นๆ อาจได้ยินผิด (เช่น "กระโดด" กลายเป็น "จะโดด") ให้อ่านเทียบกับ reference transcript เสมอ
- flag `retake_of` / `retaken_by` เป็นแค่คำใบ้ ต้องอ่านเนื้อหาจริงเพื่อตัดสินเอง
- ถ้าต้องตัดกลาง unit (เอาครึ่งเดียว หรือ unit มีคำค้างติดท้าย) ให้ใช้ `refine_speech(path, start, end)` เพื่อหาขอบคำ

## ขั้นที่ 3: กฎการเลือกและตัด

**ตัดออกเสมอ**
- slate/นับถอยหลัง/"แอคชั่น", ช่วงเงียบตาย (dead air)
- false start: ประโยคที่พูดไม่จบแล้วเริ่มใหม่, คำติดอ่าง, คำพูดค้าง
- คำเติม (เอ่อ อ่า อืม) เว้นแต่ช่วยจังหวะ/อารมณ์จริงๆ
- ข้อมูลที่พูดผิดแล้วแก้ทีหลัง (เช่น "มากกว่า 8" ที่แก้เป็น "10 กว่าปี") ให้เก็บเวอร์ชันที่แก้แล้ว
- พูดนอกบท/คุยกับทีมงาน/ถามตัวเอง (เช่น "ปีไหนนะ")

**เลือกเทคที่ดีที่สุด** (เรียงตามความสำคัญ)
1. **ครบ**: ประโยคจบสมบูรณ์ ไม่ขาดหัวขาดท้าย
2. **ถูก**: เนื้อหาเป็นเวอร์ชันที่แก้ถูกแล้ว
3. **ลื่น**: ไม่ติดขัด พลังเสียงสม่ำเสมอ
4. **เข้ากับประโยครอบข้าง**: น้ำเสียงลงท้ายเข้ากับตำแหน่ง (จบเรื่อง = เสียงลง, ยังไม่จบ = เสียงต่อ)
5. ถ้าเสมอกัน ให้เลือก**เทคหลังสุด** (ผู้พูดมักพูดใหม่จนพอใจ)

การรวมครึ่งประโยคจากคนละเทคทำได้ แต่ต้องต่อตรงช่วงหายใจ/ช่วงเงียบ และต้องผ่านการตรวจ preview

**ความต่อเนื่องของเรื่อง**
- อ่านผลลัพธ์ทั้งเรื่องแล้วต้องได้ประโยคที่สมบูรณ์ ต่อกันได้ทั้งไวยากรณ์และความหมาย
- ห้ามมีข้อมูลซ้ำซ้อน (เช่น "ผมมีคลิปเต็มในหน้าช่อง" ตามด้วย "ไปติดตามในคลิปเต็มหน้าช่อง" ให้เลือกอันเดียว) และห้ามมีคำเชื่อมลอยๆ
- ถ้าในฟุตเทจไม่มีชิ้นที่จำเป็นต่อการเล่า ให้แจ้งผู้ใช้ ห้ามแต่งเติมเอง
- ตัดที่ขอบ unit เท่านั้น ห้ามตัดกลางคำ

**วิธีตัด** (ใส่ใน segment ผ่าน `cut` = วิธีเข้าช็อตถัดไป)
- `straight` (jump cut): ค่าเริ่มต้น ใช้ระหว่างชิ้นของความคิดเดียวกัน
- `punch_in`: **ค่าเริ่มต้นคือไม่ใช้** (ไม่ส่ง `punch_in` ให้ `build_rough_cut`) เพราะการซูมสลับทุก jump cut ทำให้คลิปดูแปลก ใช้เฉพาะเมื่อผู้ใช้ขอเอง ถ้าใช้ให้อยู่ช่วง 1.08–1.15 ถ้าต้องเอาซูมออกจาก timeline ที่สร้างไปแล้ว ใช้ `set_clip_transform(timeline, track=1, zoom=1)`
- `L` (4–8 เฟรม): ภาพตัดไปก่อนแล้วเสียงเดิมพูดต่อ ใช้ตอนจบประโยคแล้วขึ้นประโยคหรือประเด็นใหม่ ช่วยให้รอยต่อนุ่มขึ้น
- `J` (4–8 เฟรม): ได้ยินเสียงช็อตถัดไปก่อนเห็นภาพ ใช้กับคำตอบ/ปฏิกิริยา/เปลี่ยนเรื่อง ต้องมีช่วงเงียบก่อนประโยคถัดไปอย่างน้อย 0.3 วินาที ไม่อย่างนั้นจะเห็นปากขยับไม่ตรงเสียง
- ถ้า `build_rough_cut`/`preview_rough_cut` คืน warnings ให้ลด `cut_frames` หรือเปลี่ยนเป็น straight

**จังหวะ**: `pace` คือระยะเผื่อหน้า/หลังคำพูด (tight 0.05/0.10s, natural 0.10/0.25s, relaxed 0.15/0.45s) ปรับรายชิ้นได้ด้วย `head`/`tail`
- **ค่าเริ่มต้น = tight** ช่องว่างระหว่างท่อนราว 0.15s ถ้าช่องว่างยาวกว่านี้ (relaxed ≈0.6s) ฟังแล้วเป็นท่อนๆ ไม่เป็นธรรมชาติ
- segment ที่ตามหลัง L-cut ให้ใส่ `head: 0.13` (≈4 เฟรม) เพื่อให้ L-cut 4 เฟรมไม่เตือนเรื่องปากขยับ และใช้ `cut_frames: 4`
- จบฉาก/ประเด็นใหญ่ใส่ `tail: 0.5` พอ ไม่ต้องยาวกว่านี้
- ถ้า tail ล้นไปโดนคำถัดไปในต้นฉบับ (ช่องว่างในต้นฉบับสั้นกว่า tail) ให้ลด tail ของ segment นั้นเหลือ 0.1

## ขั้นที่ 4: เสนอแผน (รอผู้ใช้อนุมัติ)
แสดงตาราง:

| # | ไฟล์ | เวลา | ข้อความ | เลือกเพราะ | ตัดเข้าช็อตถัดไป |
|---|---|---|---|---|---|

ตามด้วย:
- **ที่ตัดออก**: สรุปเป็นกลุ่ม (เทคซ้ำ x ครั้ง, พูดผิด, ช่วงเงียบ) พร้อมเหตุผลของการตัดสินใจที่ไม่ชัด
- **ทางเลือก** ในจุดที่ตัดสินใจได้หลายแบบ (เช่น ใช้ unit 45 หรือ 54 เป็นประโยคปิด)
- ความยาว: ก่อน → หลัง

ก่อนส่งแผน ให้เรียก `preview_rough_cut(segments, pace)` แล้วอ่าน transcript ของผลลัพธ์ ถ้ามีคำซ้ำ/ขาด/ค้าง ให้แก้แล้ว preview ใหม่ แล้วแนบ path ไฟล์ `.wav` ให้ผู้ใช้กดฟังได้

## ขั้นที่ 5: สร้างจริง (หลังอนุมัติ)
1. `build_rough_cut(name, segments, pace="tight", width/height ถ้ากำหนด)` (ไม่ส่ง `punch_in` เว้นแต่ผู้ใช้ขอ) จะสร้างเป็น timeline ใหม่เสมอ ไม่แตะของเดิม
2. `open_page("edit")`
3. รายงานผล: ความยาวก่อน/หลัง, จำนวนจุดตัด, จำนวน J/L และ warnings
4. บอกขั้นต่อไปที่ทำได้: ทำซับ (ฟังก์ชัน 2: davinci-subtitles), ใส่ B-roll, export

## ฟุตเทจยาวหลายไฟล์
- วิเคราะห์ทีละไฟล์และวางแผนทีละช่วงเรื่อง ถ้าเกิน ~60 unit ให้ส่งแผนเป็นช่วงๆ
- segment ข้ามไฟล์ได้ (ใส่ `path` ต่างกัน)
- การวิเคราะห์ครั้งแรกใช้เวลาประมาณ 1/3 ของความยาวไฟล์ ครั้งต่อไปใช้ cache ควรบอกผู้ใช้ล่วงหน้า
