# ฟังก์ชัน 4: เพลงประกอบ + SFX

เป้าหมายคือใช้เสียงคุมอารมณ์และจังหวะ เช่น มุกต้องตบให้ขำ จุดหักมุมต้องกระแทก ช่วงลุ้นต้องค้าง และตอนจบต้องทำให้อยากดูต่อ โดยเสียงพูดต้องชัดเสมอ

ผู้ใช้เป็นคนกำหนดงาน และต้องอนุมัติแผนพร้อมไฟล์ฟังตัวอย่างก่อนวางจริง

## ขั้นที่ 0: เช็คความพร้อม
- `resolve_status` และห้ามสลับโปรเจกต์เอง
- `audio_library` แสดงคลังที่ตั้งไว้ใน `library.json` (ค่าเริ่มต้นคือ `~/Desktop/Agent-M/SFX` และ `~/Desktop/Agent-M/MUSIC` รวมถึงเพลง 2 ไฟล์ที่วางอยู่ใน Agent-M) ถ้าผู้ใช้มีโฟลเดอร์อื่น ให้แก้ library.json

## ขั้นที่ 1: Brief (ถามเฉพาะข้อที่ยังไม่รู้ พร้อมค่าแนะนำ)

| ข้อ | ค่าแนะนำ |
|---|---|
| timeline | timeline ปัจจุบัน (ต้องสร้างด้วย build_rough_cut / build_timeline) |
| โทนของเรื่อง | อ่านจากเนื้อหาหรือสคริปต์แล้วเสนอ: ตลก / ลึกลับ-ลุ้น / ดราม่า / โศกนาฏกรรม-จริงจัง |
| ความถี่ SFX | คลิปยาว 1 ครั้งต่อ 8–15 วิ / คลิปสั้น 1 ครั้งต่อ 2–4 วิ |
| เพลง | เลือกจากคลังตามอารมณ์ ("ท่อนเดือด" = บู๊/เร้าใจ, "ท่อนตื่นเต้น" = ลุ้น/เล่าเรื่อง) |
| ระดับเพลง | -12 dB เทียบเสียงพูด (พูดเยอะ -14 ถึง -18, ช่วง montage ไม่มีเสียงพูด -6 ถึง -8) |
| สคริปต์ | ถ้ามีไฟล์สคริปต์ในโฟลเดอร์เรื่อง (เช่น `*_script_v2.md`) ให้อ่านเพื่อหามุกและจุดหักมุม |

## ขั้นที่ 2: อ่านจังหวะ
- `sfx_cue_map(timeline)` ให้ทุกประโยคพร้อม `pause_after`, จุดตัด, จุดที่ B-roll/มีมเข้า และคำที่เน้นในซับ
- `audio_library()` ให้ข้อมูล SFX: `sync` (วินาทีที่กระแทก), `shape`, ความดัง และข้อมูลเพลง: BPM และกราฟพลังงาน

## ขั้นที่ 3: หาจุดและเลือกเสียง

| จังหวะ | หาจากไหน | เสียงที่เหมาะ | วิธีวาง |
|---|---|---|---|
| **ตบมุก** | ประโยคที่เป็นมุก/ประชด/เรื่องเหลือเชื่อ ที่ `pause_after` ≥ 0.25 | comedy (boing, failure-trumpet, wrong-answer, nooo, among-us), meme | `at` = จบประโยค + 0.05–0.15 วิ ห้ามทับคำที่เป็นมุก |
| **กระแทกอารมณ์ / เปิดเผย** | คำสำคัญ ตัวเลข ชื่อ คำที่เน้นในซับ จุดหักมุม | impact (vine-boom, hit) | `at` = ต้นคำนั้น (align sync) ระดับ loud ใช้ไม่เกิน 1 ครั้งต่อ 10–15 วิ |
| **เปลี่ยนฉาก** | CUT / OVERLAY-IN (B-roll เต็มจอ) | transition (whoosh, swoosh) | `at` = จุดตัด ระดับ soft |
| **ภาพหรือการ์ดโผล่** | OVERLAY-IN แบบ pip/meme, ภาพถ่าย, เอกสาร | ui (pop, camera-shutter, typing, click) | `at` = ตอนการ์ดเข้า ระดับ soft–subtle |
| **ข่าวดี / เงิน / สำเร็จ** | เนื้อหาเชิงบวก ตัวเลขเงิน | positive (ding, success) | ต้นคำ ระดับ normal |
| **ลุ้น / ค้าง** | ก่อนเฉลย, คำถาม ("จะเป็นยังไง") | swell / riser ที่จบตรงจุดเฉลย, tension | `align: "end"` ให้พีคตรงจุดเฉลย ถ้าทำได้ให้เพลงเบาลงหรือเงียบก่อนเฉลย 0.3–0.6 วิ แล้วตามด้วยเสียงกระแทก |
| **ทำให้อยากดูต่อ** | ประโยคปิด / CTA / open loop | whoosh + เพลง fade out ตรงคำสุดท้าย | |

**ข้อห้าม**
- **เรื่องโศกนาฏกรรมจริง** (มีคนตาย บาดเจ็บ ภัยพิบัติ ก่อการร้าย เครื่องบินตก) ห้ามใช้ SFX ตลกหรือมีมเด็ดขาด ใช้ได้เฉพาะ impact เบาๆ เสียงสร้างความตึงเครียด และ whoosh เท่านั้น
- ห้ามวาง SFX ทับคำสำคัญจนฟังไม่ชัด และห้ามใช้เสียงเดิมซ้ำติดกันเกิน 2 ครั้ง
- SFX 2 ตัวต้องห่างกันอย่างน้อย 0.4 วิ ยกเว้นตั้งใจซ้อน เช่น whoosh + hit ที่จุดตัดเดียวกัน
- ใส่น้อยแต่โดนดีกว่าใส่ทุกประโยค

**เพลง**
- เลือกตามโทน ใช้ `hit_at` ให้จุดที่เพลงพุ่ง (`energy_jumps_at`) ตรงกับจุดหักมุมของเรื่อง
- fade in 0.5–1 วิ, fade out 1.5–3 วิ ให้จบหลังคำสุดท้ายเล็กน้อย
- `duck: true` เสมอเมื่อมีเสียงพูด (เพลงจะลดลงประมาณ 8–10 dB ตอนพูดโดยอัตโนมัติ)
- ถ้าเปลี่ยนอารมณ์กลางเรื่อง ให้แบ่งเป็นหลายช่วง (ช่วงไม่ซ้อนกัน) โดยแต่ละช่วงมี fade

## ขั้นที่ 4: เสนอแผน + ไฟล์ฟังตัวอย่าง
| เวลา | เหตุการณ์ / ประโยค | SFX | เหตุผล | ระดับ |
|---|---|---|---|---|

ตามด้วยแผนเพลง (เพลงไหน, ช่วงไหน, จุดพุ่งตรงกับคำไหน) จากนั้นเรียก `preview_audio_mix(timeline, music, sfx)` แล้วส่ง path ไฟล์ mp3 ให้ผู้ใช้กดฟัง และรออนุมัติ

## ขั้นที่ 5: วางลง timeline
1. `place_audio(timeline, music, sfx)` จะวางบน audio track "Music" และ "SFX" (ถ้าซ้อนกันจะเพิ่ม "SFX 2") เรียกซ้ำจะแทนที่ track เหล่านี้ และถ้าส่ง `music=None` จะไม่แตะ track เพลง
2. `open_page("edit")` แล้วรายงานจำนวน SFX, เพลงที่ใช้ และระดับเสียงพูดที่วัดได้
3. แก้ทีละจุดได้ เช่น ผู้ใช้สั่ง "เอา boing ออก" หรือ "vine-boom ดังไป" ให้เรียก `place_audio` ใหม่ด้วยรายการที่แก้แล้ว
