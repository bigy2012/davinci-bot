# ฟังก์ชัน 2: ซับไตเติลภาษาไทย

เป้าหมายคือซับที่**ถูกต้องตามที่พูดและตามบริบท** อ่านทันในเวลาที่ขึ้น ไม่ล้นจอ และไม่บังหน้า สำหรับคลิปสั้นต้องดึงสายตาคนดูตลอดเวลา

ผู้ใช้เป็นคนกำหนดงานทุกครั้ง และต้องอนุมัติข้อความกับภาพตัวอย่างก่อนเรนเดอร์จริง

## ขั้นที่ 0: เช็คความพร้อม
- `resolve_status` ถ้า bridge ไม่ตอบ ให้บอกผู้ใช้ไปที่ Workspace → Scripts → DaVinci Bot Bridge
- ห้ามสลับโปรเจกต์ใน Resolve เอง ผู้ใช้อาจกำลังใช้งานอยู่ใน session อื่น

## ขั้นที่ 1: Brief (ถามเฉพาะข้อที่ยังไม่รู้ รวมเป็นข้อความเดียว พร้อมค่าแนะนำ)

| ข้อ | ตัวเลือก | ค่าแนะนำ |
|---|---|---|
| timeline | ชื่อ timeline (ดูได้จาก `list_timelines`) | timeline ปัจจุบัน |
| ประเภท | คลิปยาว / คลิปสั้น | ดูจากขนาดภาพ: แนวตั้ง = สั้น, แนวนอน = ยาว |
| สไตล์ (สั้น) | `pop` / `karaoke` / `box` | `pop` |
| สไตล์ (ยาว) | `clean` | `clean` |
| แบบซับคลิปยาว | subtitle track (แก้ใน Resolve ได้ และส่งขึ้น YouTube ได้) / เบิร์นลงภาพ (overlay) | subtitle track |
| การเน้นคำ (สั้น) | ไม่เน้น / พอดี / เยอะ | พอดี |
| ฟอนต์/สีแบรนด์ | ถ้ามี | ตามสไตล์ |
| คำเฉพาะ | ชื่อคน ชื่อสถานที่ ตัวเลข ศัพท์ (หรือสคริปต์) | ถ้ามีให้ใช้สะกดตาม |

`draft_captions` ใช้ได้เฉพาะ timeline ที่สร้างด้วย `build_rough_cut`/`build_timeline` ถ้าผู้ใช้ตัดเองใน Resolve ให้ render timeline เป็นไฟล์ก่อน (`render`) แล้วใช้ `source_path`

## ขั้นที่ 2: ร่าง
`draft_captions(timeline, mode="short"|"long")` จะได้ซับพร้อมเวลา โดยแบ่งคำไทยไว้แล้ว ไม่ตัดกลางคำ และไม่ให้ครับ/นะขึ้นต้นซับ

## ขั้นที่ 3: ตรวจแก้ตามบริบท (สำคัญที่สุด)
ข้อความมาจาก Whisper ซึ่งฟังผิดได้ในช่วงสั้นๆ (เช่น "จะโดด" ที่ถูกคือ "กระโดด", "ข้าวคนนี้" ที่ถูกคือ "เขาคนนี้", "พบกับ" ที่ถูกคือ "พร้อมกับ")
- อ่านทั้งเรื่องแล้วแก้คำผิดตามบริบท เทียบกับ reference transcript จาก `analyze_speech` และสคริปต์หรือคำเฉพาะของผู้ใช้
- ซับต้องตรงกับที่พูด ตัดได้เฉพาะคำเติม (เอ่อ อ่า) และคำที่พูดซ้ำโดยไม่ตั้งใจ ห้ามเปลี่ยนความหมาย
- ชื่อเฉพาะและตัวย่อสะกดให้ถูก (FBI) ตัวเลขใช้แบบที่อ่านง่าย (1971, 2 แสนดอลลาร์)
- ห้ามแยกตัวเลขกับหน่วย (2 แสน | ดอลลาร์) และห้ามแยกคำประสม (คลิป | เต็ม)
- รวมหรือแยกซับได้ตามจังหวะพูด โดยใช้เวลาเดิมของซับนั้นๆ รวมกัน

**ความยาว**
| | ตัวอักษรต่อบรรทัด* | บรรทัด | เวลาบนจอ |
|---|---|---|---|
| คลิปยาว | ≤ 38 | 1 (สูงสุด 2) | 0.9–6 วิ |
| คลิปสั้น | ≤ 16 | 1 (สูงสุด 2) | 0.35–2.5 วิ |

\* นับเฉพาะตัวที่กินที่แนวนอน สระบนล่างและวรรณยุกต์ไม่นับ ถ้ายาวเกิน ตัวเรนเดอร์จะย่อฟอนต์ให้เอง แต่ควรแบ่งซับให้สั้นตั้งแต่แรก

**การเน้นคำ (คลิปสั้น)**: ครอบคำด้วย `*คำ*`
- เน้นคำที่ทำให้หยุดดู: ตัวเลข, ชื่อ, คำกริยาที่มีพลัง, คำที่เป็นประเด็นหลัก, คำเปิดเรื่องในซับแรก
- เน้นได้ไม่เกิน 1 วลีต่อซับ ระดับ "พอดี" ≈ 1 ทุก 2–3 ซับ, ระดับ "เยอะ" ≈ 1 ทุก 1–2 ซับ
- คลิปยาวไม่ต้องเน้น

## ขั้นที่ 4: ภาพตัวอย่าง (ตรวจไม่ล้นจอ ไม่บังโฟกัส)
`preview_captions(timeline, [2–4 ซับ], mode, style, overrides)` โดยเลือกซับที่ยาวที่สุด 1 อัน กับซับที่มีคำเน้นอีก 1 อัน แล้วใช้ Read เปิดดูภาพ:
- ซับต้องไม่ทับตา/ปาก/หน้า หรือสิ่งที่คลิปกำลังโชว์
- คลิปแนวตั้งห้ามเข้าแถบแดง ซึ่งเป็นพื้นที่ที่ปุ่มและคำบรรยายของ Shorts/Reels/TikTok บัง
- ต้องไม่ชิดขอบจอ และอ่านออกบนพื้นหลังจริง
- ปรับด้วย `overrides`:
  - `y`: ตำแหน่งแนวตั้ง (0–1) คลิปพูดแนวตั้งมักใช้ 0.62–0.75 (ใต้คาง) ถ้าหน้าอยู่ล่างให้ย้ายไปบน 0.22–0.32 ส่วนคลิปยาวใช้ 0.88–0.92
  - `size_scale`: เช่น 0.9 หรือ 1.15
  - `max_width`, `font`, `color`, `highlight_color`, `emph_color`, `stroke_color`
  - `enter` (pop|slide|fade|none), `highlight` (word|karaoke|null), `box`, `box_colors`, `shadow`

ส่งให้ผู้ใช้ดู: path ภาพตัวอย่าง + ตารางซับ (id | เวลา | ข้อความ) + สไตล์ที่ใช้ แล้วรออนุมัติ

## ขั้นที่ 5: ใส่ลง timeline
`render_captions(timeline, captions_list, mode, style, overrides, output)`
- คลิปสั้น (`overlay`): เรนเดอร์ 1 ไฟล์ใส (ProRes 4444) ต่อ 1 ซับ แล้ววางบน video track ชื่อ "Captions" ผู้ใช้ลาก/ลบทีละซับใน Resolve ได้ ถ้าเรนเดอร์ใหม่จะแทนที่ track นี้ทั้งหมด
- คลิปยาว (`track`): ใส่ไฟล์ .srt ลง subtitle track ซึ่งแก้ข้อความใน Resolve ได้ ฟอนต์ของ subtitle track ตั้งใน Inspector ของ Resolve (แนะนำ Noto Sans Thai หรือ Sukhumvit Set)
- ทุกครั้งจะได้ไฟล์ `.srt` + `captions.json` ไว้ใช้อัปโหลดหรือแก้ไขต่อ

แล้ว `open_page("edit")` และรายงานผล: จำนวนซับ, สไตล์, เวลาที่ใช้เรนเดอร์, ตำแหน่งไฟล์ .srt

## แก้ไขภายหลัง
ผู้ใช้สั่งแก้ข้อความ สี หรือตำแหน่ง ให้เรียก `render_captions` ใหม่ด้วยรายการที่แก้แล้ว (track "Captions" จะถูกแทนที่) ไม่ต้องร่างใหม่
